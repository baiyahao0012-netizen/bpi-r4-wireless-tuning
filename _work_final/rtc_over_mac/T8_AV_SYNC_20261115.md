# T8：双 session 音视频 + RTCP SR + A/V 同步（本地回环）

日期：2026-11-15  
范围：**本地回环**（Pi 上 sender/receiver 两进程），GStreamer 1.26.2  
结构参照官方示例：`gst-plugins-good/tests/examples/rtp/client-rtpaux.c`（video session 0 + audio session 1，各自 jitterbuffer 与 RTCP）

| 验收项 | 状态 | 证据 |
|---|---|---|
| 双 session（视频 + 音频，各自抖动缓冲） | ✅ | 视频 300/300 帧；音频 10.02 s（501 个缓冲） |

## 2. 管线与端口

```text
sender   anchor.mkv -> matroskademux
           video -> h264parse -> rtph264pay(96)   -> rtpbin.send_rtp_sink_0
           audio -> opusparse  -> rtpopuspay(111) -> rtpbin.send_rtp_sink_1
         rtpbin.send_rtp_src_0  -> udpsink 5004 ; _1 -> udpsink 5008
         rtpbin.send_rtcp_src_0 -> udpsink 5006 ; _1 -> udpsink 5010
         udpsrc 5005 -> recv_rtcp_sink_0 ; udpsrc 5009 -> recv_rtcp_sink_1

receiver udpsrc 5004 (8MB) -> recv_rtp_sink_0 ; udpsrc 5008 (8MB) -> recv_rtp_sink_1
         recv_rtp_src_0_* -> rtph264depay -> h264parse -> avdec_h264
                          -> videoconvert -> I420 320x180 -> filesink
         recv_rtp_src_1_* -> rtpopusdepay -> opusdec -> audioconvert
                          -> S16LE mono 48k -> filesink
         send_rtcp_src_0/1 分别接 udpsink 5005 / 5009
```

## 3. 实测

### 3.1 媒体量

| 流 | 实测 | 理论 |
|---|---|---|
| 视频 | **300 帧**（320×180 I420，25.9 MB） | 10 s × 30 fps = 300 |
| 音频 | **501 个缓冲，961,920 B = 480,960 样本 = 10.02 s** | 10 s × 48 kHz = 480,000 样本 |

### 3.2 RTCP SR 的 NTP↔RTP 映射

30 秒合成源（`videotestsrc` + `openh264enc` / `audiotestsrc` + `opusenc`），接收端每次收到 SR 记录 `(SSRC, NTP, RTP 时间戳)`，每路 8 个样本，线性拟合：

| 流 | 拟合斜率 | 理论时钟 | 偏差 |
|---|---:|---:|---:|
| 视频 | **89,999.991** | 90,000 | -0.009（1e-7 相对误差） |
| 音频 | **48,000.002** | 48,000 | +0.002 |

把两路都映射到同一 NTP 时钟后，媒体时间差：

- 标准差 **3 µs**，跨度 **10 µs**
- 由斜率差推算 30 秒漂移 **-0.005 ms**

即：两个 session 的 SR 指向同一个时钟，且各自的 NTP→RTP 换算速率正确。

### 3.3 A/V 锚点偏差

锚点素材：每秒 1 整帧纯白 + 50 ms 1 kHz 短音。落盘裸流后用 `test_harness/l0_verify/av_skew.py` 分析：

```json
{"flash_frames": 10, "tone_bursts": 10, "pairs": 10,
 "skew_ms": [0,0,0,0,20,20,20,20,0,0],
 "skew_p50_ms": 0, "skew_p95_ms": 20, "skew_max_ms": 20, "aligned": true}
```

p95 = 20 ms 来自 20 ms RMS 检测窗，与 L0 的源基线（0/20/20）一致，**不是媒体层引入的偏差**。

## 4. 踩过的坑（按官方资料核对后修正）

| 现象 | 原因 | 修正 |
|---|---|---|
| 接收端 0 字节输出 | rtpbin 的 RTP 输出 pad 模板是 **`recv_rtp_src_%u_%u_%u`**（session, ssrc, pt），我按 `recv_rtp_src_0` 精确匹配 | 用 `startswith("recv_rtp_src_0_")` / `_1_` |
| RTCP 不发出 | `send_rtcp_src_%u` 在 Python 里不会自动出现 | 显式 `request_pad_simple("send_rtcp_src_0/1")` 再连 udpsink |
| 合成源缺 `x264enc` | Pi 未装 gst-plugins-ugly | 改用 `openh264enc`（bad 插件集，已装） |

## 7. 真实链路复测（Pi → AP → 笔记本，2026-11-15 晚）

拓扑：Pi `wlan1` 192.168.240.126 → BPI-R4 AP（仅 bridge）→ 笔记本 192.168.240.2。  
发送端在 Pi（`--host 192.168.240.2 --bind-address 192.168.240.126`，源地址绑定保证走无线口）；接收端在笔记本用两个 `gst-launch` 进程（视频/音频各一个 `rtpbin`，单会话），落盘裸流后跑同一个 `av_skew.py`。

| 项 | 结果 |
|---|---|
| 视频 | **300 帧**（25,920,000 B） |
| 音频 | **470,400 样本 = 9.8 s**（940,800 B） |
| 音画偏差 | 10 对锚点，偏差 0/0/0/0/20/20/20/20/0/0 ms，**p50 = 0、p95 = 20 ms**，与本地回环完全一致 |
| 跨机时钟 | ⚠️ 未能精确测量（见下） |

### 7.1 踩坑：Windows 防火墙拦 gst-launch 的入站 UDP

现象：接收端管线进入 PLAYING，但落盘 0 字节；同一端口用 Python 的 UDP 程序能收到 323 个包（源地址 .126）。

定位：本机回环用同一条接收管线跑 60 帧合成源，落盘 5,184,000 字节（60 × 86,400）——**管线本身没问题**。差异只在"入站方向"：Python 在放行名单里，`gst-launch.exe` 没有。

绕过：用 Python 做本地中继（`tools/udp_relay.py`，5004→6004、5008→6008），gst-launch 只听回环。RTP 内容原样转发，不解析、不改时间戳；RTCP 仍由 gst-launch 直发 Pi。中继在环回上引入的延迟 < 1 ms，不影响 A/V 偏差结论。

> 正式部署应给 `gst-launch.exe` 加防火墙入站规则（需要管理员），而不是长期依赖中继。

### 7.2 跨机时钟

- Windows 时间服务（`w32time`）仍为 Stopped/Manual，本会话无管理员权限，`Start-Service` 失败；
- 用 SSH 往返估算 Pi 与 Windows 的偏差：host 前后时刻 1794750314.742 / .937，Pi 读数 .951，**RTT 195 ms → 偏差估计 +111 ms，误差约 ±97 ms**，不足以作为 A/V 对账依据；
- 本次 A/V 偏差**不依赖跨机时钟**：两路流由同一接收进程按解码顺序落盘，偏差是接收端内部相对量，跨机 offset 自动抵消。跨机时钟只在"用发送端 SR 的 NTP 与接收端墙钟对账"时才需要。

### 7.3 复现

```bash
# 接收端（Windows，两个进程；端口经中继为 6004/6008）
gst-launch-1.0 -e rtpbin name=r rtp-profile=avpf \
  udpsrc port=6004 buffer-size=8388608 caps="application/x-rtp,media=video,encoding-name=H264,payload=96,clock-rate=90000" ! r.recv_rtp_sink_0 \
  r. ! rtph264depay ! h264parse ! avdec_h264 ! videoconvert ! videoscale ! video/x-raw,format=I420,width=320,height=180 ! filesink location=video.yuv \
  r.send_rtcp_src_0 ! udpsink host=192.168.240.126 port=5005 sync=false async=false \
  udpsrc port=5006 ! r.recv_rtcp_sink_0
# 音频同结构，端口 6008 / RTCP 5009、5010
# 发送端（Pi）
python3 tools/t8_av_lab.py sender --file /home/bai/rtc_test/anchor.mkv \
  --host 192.168.240.2 --bind-address 192.168.240.126 --seconds 11
```
