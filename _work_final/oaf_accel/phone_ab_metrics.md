# 手机豆包加速 A/B 指标分析（2026-10-29）

## 测试条件

- 手机 192.168.240.219 连 BPI-R4-5G AP；
- 板子 WAN 走 DianGroup103；
- PC WLAN3 192.168.240.126 + 自带 WLAN 192.168.240.147 同时 iperf3；
- 每轮 180 s；
- 基线：无 oaf_accel 规则；
- 加速：oaf-auto 自动安装 EF 规则；
- AP 侧 tcpdump 抓手机 TCP。

## 吞吐

| 组 | WLAN3 | 自带 WLAN | 合计 |
|---|---|---|---|
| 基线 | 255 Mbit/s | 24.5 Mbit/s | 279.5 Mbit/s |
| 加速 | 258 Mbit/s | 24.6 Mbit/s | 282.6 Mbit/s |

总吞吐基本不变：+1.1%。

## 机制层

| 指标 | 基线 | 加速 |
|---|---|---|
| nft 规则 | 不存在 | 存在 |
| nft counter | — | 844 packets / 449,479 B |
| 手机 mark=1900 | 3 | 2 |
| 手机 pcap EF 包 | 5 | 132 |
| 手机 pcap TCP 包 | 2479 | 2878 |

加速组 EF 包明显增加，说明 DSCP/规则命中。

## 传输层（AP pcap）

| 指标 | 基线 | 加速 |
|---|---|---|
| SYN RTT p50 | 55.9 ms | 75.5 ms |
| SYN RTT p95 | 138.6 ms | 291.9 ms |
| TCP TS RTT p50 | 66.6 ms | 62.8 ms |
| TCP TS RTT p95 | 1955 ms | 1955 ms |
| 重传数 | 39 | 58 |

- p50 略降 3.8 ms；
- p95 基本不变；
- SYN RTT 和重传反而变差；
- 差异小，不能证明体验改善。

## 体验层（PC TTFB，10 次）

| 指标 | 基线 | 加速 |
|---|---|---|
| 均值 | 0.703 s | 0.760 s |
| p50 | 0.687 s | 0.732 s |
| p95 | 0.929 s | 0.881 s |

p95 略降，p50 略升；差异在噪声范围。

## 判定

- L2 识别：通过；
- L3 规则/EF：通过（EF 5→132，counter 844）；
- L4/L5：无明确改善；
- L1 公平性：总吞吐 279.5→282.6，稳定。

结论：

> 加速链路已经工作，但当前 5G HE80 + 约 280 Mbit/s 负载没有形成足够拥塞，不能证明豆包体验改善。

下一步应在 HE40/2.4G 或更强干扰下重复同样 A/B，并抓手机侧连续操作。
